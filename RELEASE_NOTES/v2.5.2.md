## Patch Sage Attention DM — Native Attention Restoration, Comfy Kitchen Backend & Blackwell Kernel Routing

### Summary

In **v2.5.2**, the **Patch Sage Attention DM** node (`nodes/sa.py`) merges [PR #5](https://github.com/ussoewwin/ComfyUI-DistorchMemoryManager/pull/5) by [@IrradiatedHaggis](https://github.com/IrradiatedHaggis) — *SA Patch Node restores previously set user attention rather than forcing FA2*. The cleanup path now restores the attention backend ComfyUI had configured from its startup arguments instead of forcing Flash-Attention, and an override installed by another component survives the cleanup pass.

On top of the merged branch this release adds two selectable backends (`fa2` and `comfy kitchen attention`), routes the sm80-only fp16-accumulate SageAttention mode to the fp8 kernel on Blackwell, fixes an undefined name that forced every SageAttention mode onto PyTorch attention, and renames the node and its widget key to `accel` terminology.

---

### Merged Pull Request: PR #5

#### 1. Cleanup restores the configured backend
- **Before**: the cleanup callback always re-installed `attention_flash`, so a session started with `--use-pytorch-cross-attention` (or any other backend) ended up on Flash-Attention once the node released the model.
- **After**: `_restore_previous()` puts back the exact override captured before the node patched, and removes the override entirely when there was none. The global `comfy.ldm.modules.attention.optimized_attention` object is never rewritten.

#### 2. The cleanup log reports the backend that is actually active
- **Before**: the restore line printed Flash-Attention information regardless of what had been restored.
- **After**: `report_flash` gates that line. `disabled` prints the restore line only; the modes that install a backend keep the two-line form the node has always produced.

#### 3. An override installed by another component is preserved
- **Issue**: a node that patches attention after this one (for example a sparse-attention node) installs its own `optimized_attention_override`. The previous cleanup replaced it with the state captured at patch time.
- **After**: cleanup compares the live override against the one this node installed. When they differ, the other component's override is left in place and only a restore line is logged.

---

### New Attention Backends

1. **`fa2`** — selects Flash-Attention explicitly.
   - Resolves the installed `flash-attn` build and logs `[ComfyUI] Using FA-2|FA-3 (Flash-Attention <version>) direct`.
   - When `flash-attn` cannot be imported, the node logs the reason, keeps the previously configured backend, and does not install an override.

2. **`comfy kitchen attention`** — Comfy Kitchen INT8 attention, resolved the same way ComfyUI's own **Model Attention Backend** node resolves it.
   - `comfy_attention.get_attention_function("comfy_kitchen_int8", None)` is asked for the backend with no default, so an unregistered backend falls back to PyTorch attention with ComfyUI's own warning text: `Attention backend 'comfy kitchen attention' is unavailable; using PyTorch attention.`
   - The override is shaped exactly like `ModelPatcher.set_model_optimized_attention`, including carrying `container_function` over from the resolved backend. Attention-tensor containers therefore keep the `prequantize_int8_attention` → `int8_attention_from_prequantized` path, with the same peak-memory behaviour as the native node.
   - The resolved build is logged like the SageAttention modes: `Patching comfy attention to use Comfy Kitchen <version>+cu<cuda>torch<torch>`.

---

### Blackwell Kernel Routing

- **Issue**: `sageattn_qk_int8_pv_fp16_cuda` is built for `sm_80` only (`setup.py` gates `_qattn_sm80` to `["8.0"]`). On sm100/sm120/sm121 the call raises `CUDA error: no kernel image is available for execution on the device`.
- **After**: on sm100/sm120/sm121 that option resolves to `sageattn_qk_int8_pv_fp8_cuda` with `qk_quant_gran="per_warp"` and `pv_accum_dtype="fp32+fp16"` (`"fp32"` below CUDA 12.8), matching `sageattention/core.py`'s own dispatcher. The dispatch is logged once: `SageAttention: sm120 has no fp16-accumulate kernel; using the fp8 kernel (qk_quant_gran=per_warp, pv_accum_dtype=fp32+fp16)`.
- The option label carries the constraint: `sageattn_qk_int8_pv_fp16_cuda (for only sm80)`.

---

### Defect Fixes

1. **Undefined `is_causal` forced every SageAttention mode onto PyTorch attention**
   - The wrapper call referenced an undefined `is_causal` name, so each SageAttention mode raised `NameError: name 'is_causal' is not defined` and ComfyUI logged `Error running sage attention: ... using pytorch attention instead.`
   - The call now passes `is_causal=False`, the value ComfyUI's own `attention_sage` passes (`attention.py`).
2. **Duplicated version suffix in the attention log line**
   - `sageattention.__version__` already carries a local tag (`2.2.0.post6+cu134torch2.15.0`), and the line appended `+cu<cuda>torch<torch>` on top of it.
   - The suffix is now appended only when the package version has no local tag. `torch.version.__version__` (which returns the full `2.15.0+cu134`) was also replaced with the release part.

---

### Node Rename and Widget Key

- Display name: `Patch Sage Attention DM` → **`Patch Accel Attention DM`** (`NODE_DISPLAY_NAME_MAPPINGS`, `__init__.py`).
- Widget key: `sage_attention` → **`accel_attention`**. Option values are unchanged, so saved workflows keep their kernel identifiers.
- The class name `PatchSageAttentionDM` and its registration key are unchanged for workflow compatibility.

### Compatibility

- Option values are unchanged; existing workflows keep working.
- `allow_compile` remains an optional input. It is ignored by `fa2` and `comfy kitchen attention`, which do not use `torch.compile`.
- Requires a ComfyUI build that registers `comfy_kitchen_int8` for the Comfy Kitchen backend. On builds without it the option falls back to PyTorch attention and says so in the log.
