## Patch Sage Attention DM — Restore the Previously Configured Attention Backend & Explicit Flash-Attention Selection

### Summary

In **v2.5.2**, the **Patch Sage Attention DM** node (`nodes/sa.py`) changes how the `disabled` option behaves and adds an explicit **`fa2`** option.

Previously, selecting `disabled` deleted the node's attention override and immediately re-installed a Flash-Attention override, and the same happened again during cleanup. The result was that the attention backend chosen through ComfyUI's startup arguments (`--use-sage-attention`, `--use-flash-attention`, `--use-ck-attention`, `--use-split-cross-attention`, ...) was replaced by Flash-Attention, while the log still reported "Restoring initial comfy attention".

From this version on, `disabled` restores the state that was captured before the node patched anything: a previously installed `optimized_attention_override` is put back, and when there was none, the key is removed so ComfyUI falls back to the backend it selected at startup. The new **`fa2`** option selects Flash-Attention explicitly, so users who want Flash-Attention can now ask for it directly instead of relying on the side effect of `disabled`.

---

### Root Cause Analysis & Empirical Findings

#### 1. The `disabled` Path Forced Flash-Attention
- **Issue**: The `disabled` branch removed `optimized_attention_override` and then wrote a Flash-Attention override back into the same key.
- **Impact**: ComfyUI applies `transformer_options["optimized_attention_override"]` with the highest priority (`comfy/ldm/modules/attention.py`), so the backend selected at startup was always overridden by Flash-Attention. The node's own tooltip described `disabled` as "revert back to normal", which did not match the behaviour.

#### 2. Cleanup Left Flash-Attention Behind
- **Issue**: The `ON_CLEANUP` callback performed the same re-installation, so the override survived the run.
- **Impact**: After the workflow finished, the model still ran with the Flash-Attention override in place, and the log printed a Flash-Attention version line instead of the backend actually in use.

#### 3. `disabled` Reported Flash-Attention Even Though It Forced It
- **Issue**: The `disabled` path printed the Flash-Attention build line because it installed a Flash-Attention override right after deleting the node's own.
- **Impact**: The line described the backend that was forced, not the backend the user had configured at startup, so the log could not be used to verify the startup selection.

---

### Detailed Changes

1. **Restore Instead of Forcing**:
   - Added `_restore_previous(model, prev_override, prev_global_attn)` in `nodes/sa.py`.
   - A previously installed `optimized_attention_override` is restored; when there was none, the key is removed so ComfyUI returns to the backend it selected from its startup arguments.
   - Both the `disabled` path and the `ON_CLEANUP` path now use this function. The Flash-Attention re-installation was removed from both.
2. **Explicit Flash-Attention Selection**:
   - Added the **`fa2`** option to the `accel_attention` selector.
   - It is served by the dedicated `get_flash_func_dm()` helper, which reuses the existing `get_flash_attention_info()` detection (version plus FA-2 / FA-3 classification) and logs the detected build.
   - When the `flash-attn` package cannot be imported, the actual reason is logged as an error and the previously configured backend is kept instead of silently changing behaviour.
3. **Cleanup Leaves Foreign Overrides Alone**:
   - If another component replaced the attention override after this node installed its own, cleanup logs that and leaves the foreign override untouched.
   - The override this node installs is tracked by identity, so the node never mistakes its own override for a foreign one.
4. **Log Output Unchanged**:
   - Every SageAttention mode (`auto`, `sageattn_*`, `sageattn3*`) prints exactly the same lines as before, on both the patch and the cleanup path.
   - `fa2` prints exactly what the previous forced-Flash-Attention path printed: `Restoring initial comfy attention` followed by `[ComfyUI] Using FA-2/FA-3 (Flash-Attention x.y.z) direct`.
   - `disabled` prints only `Restoring initial comfy attention`, because it no longer touches Flash-Attention at all.
   - The `preferred_attention` keyword argument is consumed in the SageAttention override for compatibility with newer ComfyUI versions.
5. **SageAttention Dispatch Fixed**:
   - The call into the SageAttention wrapper referenced an undefined `is_causal` name, so every SageAttention mode raised `NameError` and fell back to PyTorch attention. The call now passes `is_causal=False`, matching ComfyUI's own `attention_sage`.
   - The fp16-accumulate kernel is built for sm80 only, so on sm100/sm120/sm121 that mode is routed to the fp8 kernel with `qk_quant_gran="per_warp"`, exactly as sageattention's own dispatcher does. The option is labelled `(for only sm80)`.
6. **Documentation Alignment**:
   - Synced `README.md` and `zhmd/README.md`: the option list now documents `fa2`, and `disabled` is described as restoring the previously configured backend.
   - Updated `changelog/changelog.md` and `zhmd/changelog/changelog.md` with language-matched links.

---

### Verification

- **Test environment**: Windows 11, ComfyUI 0.43.1, PyTorch 2.15.0+cu134, flash-attn 2.9.2.post2 (FA-2), SageAttention 2.2.0.post6.
- **Measured results**:
  - A branch coverage test of the node ran 15 assertions with 0 failures: `disabled` restores a previously captured override, `disabled` removes the key when there was no previous override, `fa2` installs the Flash-Attention override, the `fa2` override dispatches to `comfy_attention.attention_flash`, `fa2` logs an error with the reason and keeps the previous backend when flash-attn cannot be imported, and cleanup leaves an override installed by another component untouched.
  - In the measured log, `fa2` reports `Restoring initial comfy attention` followed by `[ComfyUI] Using FA-2 (Flash-Attention 2.9.2.post2) direct`, byte-identical to what the previous forced-Flash-Attention path printed.
- **Upgrade recommendation**: users of `Patch Sage Attention DM` should set `accel_attention` to `disabled` to return to the backend ComfyUI selected from its startup arguments, and select `fa2` to use Flash-Attention explicitly.
