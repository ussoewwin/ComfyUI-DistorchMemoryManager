## Patch Sage Attention DM — Complete Removal of SpargeAttn Integration & Architecture Streamlining

### Summary

In **v2.5.1**, the **Patch Sage Attention DM** node (`nodes/sa.py`) completely removes the SpargeAttn integration (`spargeattn` mode and the `sparge_topk` widget). 

Extensive empirical testing and production generation runs confirmed that SpargeAttn's block-sparse execution introduces persistent process-level VRAM pollution across runs and causes progressive high-frequency noise artifacts in generated images.

To ensure pristine generation fidelity and zero-leak memory stability across long generation sessions, SpargeAttn has been cleanly eliminated, returning the node to a robust, streamlined architecture powered exclusively by standard SageAttention (SA2 / SA3) and Flash-Attention backends.

---

### Root Cause Analysis & Empirical Findings

#### 1. Persistent VRAM Pollution Across Generation Runs
- **Issue**: SpargeAttn's two-stage block-sparse filtering requires dynamic allocation and management of sparse index buffers and intermediate reduction tensors outside PyTorch's primary memory pool.
- **Impact**: In multi-step sampling and repeated generation runs, these buffers were not fully reclaimed by garbage collection (`gc.collect()`) or CUDA cache flushes (`torch.cuda.empty_cache()`), causing progressive physical VRAM creep across consecutive prompts and eventual CUDA Out-of-Memory (OOM) failures on large workflows.

#### 2. Progressive High-Frequency Noise Artifacts
- **Issue**: Forcing block-sparsity on diffusion latents via Top-K thresholding discards critical low-magnitude KV blocks containing subtle high-frequency spatial context.
- **Impact**: Over 25–50 sampling steps, the accumulated truncation error induces subtle numerical drift along the latent trajectory (divergence from the dense FP16/BF16 baseline). When decoded via VAE, this manifests as fine-grained noise grain, speckles, and texture degradation.

---

### Detailed Changes

1. **Complete Removal from Node Interface**:
   - Removed `spargeattn` from the `sage_attention` dropdown selector in `PatchSageAttentionDM.INPUT_TYPES`.
   - Removed the optional `sparge_topk` float widget.
2. **Backend & Kernel Cleanup**:
   - Completely deleted `get_sparge_func_dm()` and all SpargeAttn dispatch logic (~250 lines of specialized code) from `nodes/sa.py`.
   - Eliminated the `spas_sage_hswq_attn` package dependency and associated fallback edge cases.
3. **Streamlined Architecture**:
   - The node is now purely dedicated to verified SageAttention implementations:
     - **SageAttention 2**: `auto`, `sageattn_qk_int8_pv_fp16_cuda` / `triton`, `sageattn_qk_int8_pv_fp8_cuda` / `cuda++`
     - **SageAttention 3**: `sageattn3`, `sageattn3_per_block_mean` (Blackwell sm100/120 support)
     - **Flash-Attention**: Native ComfyUI attention / Flash-Attention 2/3 fallbacks
4. **Documentation & Asset Alignment**:
   - Synced `README.md` and `zhmd/README.md` to remove all SpargeAttn usage instructions and wheel recommendations.
   - Updated `changelog/changelog.md` and `zhmd/changelog/changelog.md` with language-matched links.
   - Restored node screenshot `png/sa.png` to the pre-SpargeAttn clean layout (commit `5dda0c0`).
