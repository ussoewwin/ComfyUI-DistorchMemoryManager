本版本在 **DisTorch Purge VRAM V2**（`DisTorchPurgeVRAMV2`）上新增 **`Ollama`** 开关，位于 **`HSWQ`** 下方，用于对 **comfyui-ollama** 与 **comfyui-ollama-describer** 占用的 **Ollama 服务端显存** 做**零残留**清理。

规范实现位于仓库根目录 **`purge_vram.py`**（由 `__init__.py` 导入）。fallback **`nodes/purge_vram.py`** 与 root 保持同步。

---

## 概述

| 项目 | 详情 |
|------|------|
| **节点** | General Purge VRAM V2 — class id `DisTorchPurgeVRAMV2` |
| **新增 UI 开关** | **`Ollama`**（位于 **`HSWQ`** 下方） |
| **目标扩展** | [comfyui-ollama](https://github.com/stavsap/comfyui-ollama)、[comfyui-ollama-describer](https://github.com/alisson-anjos/comfyui-ollama-describer) |
| **目标内存** | **外部 Ollama 服务** 的 GPU/RAM（非 ComfyUI 进程内的 PyTorch 模型） |
| **目标** | purge 后 `GET /api/ps` 返回**无已加载模型** |

---

## 为何需要

1. **Ollama 模型驻留在 Ollama 守护进程中**，不在 ComfyUI `model_management` 内。标准 ComfyUI unload 与 DistTorch 通用 purge **不会**释放它们。
2. **comfyui-ollama-describer** 默认 **`keep_model_alive=-1`**，会把模型无限期保留在服务端，直到显式卸载。
3. **`HSWQ`** purge（v2.4.1）针对 HSWQ INT8 / PinCache / kitchen 残留——与 Ollama 服务端状态是**不同**的失败类别。
4. 没有专用路径时，操作者会看到：purge 节点“完成”→ 任务管理器 / `nvidia-smi` 仍显示 Ollama 显存 → 下一步工作流冲突或 OOM。

## `Ollama` 开关做什么

在 Purge VRAM V2 上启用 **`Ollama`** 时：

### 1. 发现 Ollama 服务 URL

- 环境变量 `OLLAMA_HOST` / `OLLAMA_BASE_URL`
- 已加载的 **comfyui-ollama** / **comfyui-ollama-describer** 包中的模块级常量（`DEFAULT_URL`、`url`、`api_host` 等）
- describer 节点类 `INPUT_TYPES()` 的默认值（`api_host`、`url`）
- 通过 `gc.get_objects()` 扫描活动的 `ollama.Client` 实例与 Ollama 节点对象字段
- 回退：`http://127.0.0.1:11434`、`http://localhost:11434`

### 2. 服务端卸载循环（每个 URL，最多 8 轮）

对 **`GET /api/ps`** 报告的每个模型名：

- **`POST /api/generate`**：空 prompt，`keep_alive: 0`（以及 `"0"`）
- **`POST /api/chat`**：空 messages，`keep_alive: 0`（以及 `"0"`）
- **`ollama.Client.generate` / `.chat`**：相同的 `keep_alive=0` 语义
- 可用时执行 **`ollama stop <model>`** CLI

重复直到 **`/api/ps`** 为空或轮次用尽。每个 base URL 记录 **`FINAL VERIFY OK`** / **`FINAL VERIFY FAIL`**。

### 3. Comfy 侧状态清理

- 清空 ollama 自定义节点模块中的 **`CHAT_SESSIONS`** 字典
- 重置 Ollama 节点类上的类级 **`saved_context`**
- 删除各包 **`saved_context/`** 目录下的文件（保留 `.keep`）
- 扫描活动 Ollama 节点实例：清空 `saved_context`、`messages`、`context`、`history`、`chat_history`

### 4. 完成日志

示例摘要行：

`Ollama: Done — unload_attempts=…, sessions_cleared=…, context_attrs_cleared=…, files_wiped=…, instances_cleared=…, residual=(none)`

## 要求

- 已安装 **Ollama**，且可在收集到的 URL 上访问
- 工作流中使用时需有自定义节点 **comfyui-ollama** 和/或 **comfyui-ollama-describer**
- 可选：`ollama` Python 包（Client 回退）以及 `PATH` 上的 `ollama` CLI（用于 `ollama stop`）

---

## 升级

1. 将 **ComfyUI-DistorchMemoryManager** 更新到 **v2.4.2**（或拉取带标签 `v2.4.2` 的 `main`）。
2. 重启 ComfyUI（或重载自定义节点），以便导入根目录 **`purge_vram.py`**。
3. 在工作流中打开 **General Purge VRAM V2**，在使用基于 Ollama 的节点并需要回收服务端显存时启用 **`Ollama`**。

未使用该开关的现有工作流不受影响；**`Ollama`** 默认**关闭**。
