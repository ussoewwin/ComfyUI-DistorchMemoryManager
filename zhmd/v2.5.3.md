## 1. 问题所在

清理节点是按 ComfyUI 0.38 及之前的内存 API 编写的。此后的三项变更，使节点在信息不完整的情况下仍然报告清理成功。

### 1.1 pinned 内存迁移，旧扫描看不到新的 pin

ComfyUI 0.46 把 pin 保存在模块自身：

| 元素 | 位置 |
| :--- | :--- |
| pin 表 | `module._pins[subset]`、`module._pin_state[subset]`（`comfy/pinned_memory.py`） |
| 承载实体 | `comfy_aimdo` host buffer（`comfy_aimdo.torch.hostbuf_to_tensor`） |
| 注册记账 | `module._pins[subset]["registered"]`、`comfy.model_management.TOTAL_PINNED_MEMORY` |
| 回写 | `comfy.pinned_memory.flush_pin(module, module_pin)` |
| 完整回收 | `ModelPatcher.partially_unload_ram()`（`comfy/model_patcher.py:2202`） |

旧路径仍在，且与前者彼此独立：`comfy.model_management.pin_memory(tensor)` 把自己的注册记录在 `PINNED_MEMORY[ptr]`（`model_management.py:1606`、`:1663`），`unpin_memory(tensor)`（`:1702`）只删除该字典中存在的条目。

per-module pin **不在** `PINNED_MEMORY` 中。因此节点的 pin 扫描虽然报告 “pins unregistered = N”，comfy-aimdo 的注册以及承载这些权重的 host buffer 仍然存活。

### 1.2 fast-disk 驱动的原生调用不得与破坏性 CUDA 操作重叠

自 0.38 起，fast-disk 对所有 loader 生效。comfy-aimdo 的原生调用在设计上就是单线程的：设备上下文是线程局部的，文件读取器只有一个完成槽，流的解析使用调用线程当前的 stream。每次原生调用都会 map / unmap / evict VRAM 虚拟页（VBAR / HostBuffer）。如果某一页在另一个 stream 上仍有内核运行时被 unmap，结果就是 `CUDA_ERROR_ILLEGAL_ADDRESS`，并伴随粘性的 `result=700`，随后是 `Fatal Python error: Aborted`。

`ComfyUI-HSWQ-Loader-and-Tools` 正是记录了这一类失败，并用一个进程级的可重入锁把原生调用串行化（`patches/comfy_aimdo_fastdisk_guard.py:56` 的 `_APPLIED`、`:59` 的 `_NATIVE_LOCK`，以及该模块的 docstring）。

而清理节点执行其最具破坏性的操作——对受管 host pin 调用 `cudaHostUnregister`、销毁 INT8/NVFP4 模块的 storage、`torch.cuda.empty_cache()`——时既没有取得该锁，也没有等待异步 offload stream。因此一次 purge 有可能在拷贝进行中把页 unmap 掉。

### 1.3 0.46 的主存 RAM 缓存从未被释放

`comfy/memory_management.py` 增加了主存 RAM 缓存（`:240` 的 `RAM_CACHE_HEADROOM`、`:242` 的 `set_ram_cache_release_state()`、`:248` 的 `extra_ram_release()`）。节点声明的目的就是在大型模型卸载后回收内存，而主存 RAM 属于该范围，但节点中没有任何地方调用释放入口。

## 2. 根本原因

一个原因，三个后果。

清理实现内嵌了 0.38 期 API 的假设：*“host pin 就是 `PINNED_MEMORY` 中的条目，释放显存只是丢引用并调用 `empty_cache()`”*。该假设的两半都已不再完整：

1. **pin 状态的持有者迁到了模块内部与 comfy-aimdo host buffer。** 丢掉一个 Python 引用不再意味着“注册已被释放”，因为释放是一次调用（ComfyUI 自身回收路径中的 `hostbuf.truncate(..., do_unregister=True)`）。只读取 `PINNED_MEMORY` 的扫描，在结构上无法看到这些 pin。
2. **破坏性操作与一个禁止并发的原生子系统变成了并发关系。** 节点中没有任何地方与 offload stream 或 fast-disk 锁同步，于是节点的正确性开始取决于时序。
3. **回收目标扩大到主存 RAM，而节点并未被告知。** 节点仍只测量并报告显存。

因此修正必须且只需做三件事：(a) 取得 fast-disk guard 使用的同一个锁对象，并在破坏性区段之前把 stream 落定；(b) 通过 ComfyUI 自身的 API 回收 per-module pin，使 flush、解除注册与记账都发生在拥有它们的那一处；(c) 释放主存 RAM 缓存。

## 4. 代码全文

### 4.1 模块级辅助函数（23-148 行）

```python
# ---------------------------------------------------------------------------
# ComfyUI 0.38+ fast-disk (comfy-aimdo) and 0.46 per-module pinned memory.
#
# Measured on ComfyUI 0.46.0:
#
#  * Per-module pins live on the module (comfy/pinned_memory.py: module._pins /
#    module._pin_state) and hold comfy-aimdo host buffers. Those CUDA
#    registrations are NOT in comfy.model_management.PINNED_MEMORY, so the
#    legacy sweep in this node cannot reach them.
#    ModelPatcher.partially_unload_ram() is ComfyUI's own drain: it flushes a
#    dirty pin back to its file slice, truncates the host buffer with
#    do_unregister and keeps TOTAL_PINNED_MEMORY consistent.
#
#  * comfy-aimdo native calls are single-thread by design. The HSWQ loader's
#    comfy_aimdo_fastdisk_guard.py serialises them through one process-wide
#    RLock and documents what happens when page maps overlap in-flight kernels
#    (CUDA_ERROR_ILLEGAL_ADDRESS, sticky result=700, abort). Destructive CUDA
#    work here takes that same lock object and syncs the offload streams first,
#    so a purge never unmaps a page under an in-flight copy.
#
# Every step is independent and prints what it did or why it skipped.
# ---------------------------------------------------------------------------

_AIMDO_GUARD_SUFFIX = "comfy_aimdo_fastdisk_guard"
_PURGE_UNBOUNDED = 1 << 60


def _purge_aimdo_lock():
    """Return (lock, module_name) of the HSWQ fast-disk native lock, or (None, None)."""
    try:
        items = list(sys.modules.items())
    except Exception:
        return None, None
    for name, mod in items:
        if mod is None:
            continue
        if not str(name).endswith(_AIMDO_GUARD_SUFFIX):
            continue
        lock = getattr(mod, "_NATIVE_LOCK", None)
        if (
            lock is not None
            and callable(getattr(lock, "acquire", None))
            and callable(getattr(lock, "release", None))
        ):
            return lock, str(name)
    return None, None


def _purge_sync_offload_streams() -> bool:
    """Wait for every async offload stream before any destructive CUDA step."""
    try:
        import comfy.model_management as mm
    except Exception:
        return False
    fn = getattr(mm, "sync_all_offload_streams", None)
    if not callable(fn):
        return False
    try:
        fn()
        return True
    except Exception as e:
        print(f"VRAM purge: offload stream sync failed: {e}")
        return False


def _purge_release_ram_cache(free_active: bool = True) -> int:
    """Release the 0.46 host RAM cache (comfy.memory_management). Returns bytes."""
    try:
        import comfy.memory_management as cmm
    except Exception:
        return 0
    fn = getattr(cmm, "extra_ram_release", None)
    if not callable(fn):
        return 0
    try:
        freed = fn(_PURGE_UNBOUNDED, free_active=free_active)
    except Exception as e:
        print(f"VRAM purge: RAM cache release failed: {e}")
        return 0
    try:
        return int(freed or 0)
    except Exception:
        return 0


def _purge_drain_module_pins() -> dict:
    """Flush and unregister every per-module pin through ComfyUI's own API.

    Uses __dict__ lookups only (no dir()/getattr probing on foreign objects,
    which can trigger third-party lazy loaders), one ModelPatcher at a time.
    """
    report = {"models": 0, "freed_mb": 0.0, "failed": 0}
    patchers = []
    try:
        for obj in gc.get_objects():
            if type(obj).__name__ not in ("ModelPatcher", "ModelPatcherDynamic"):
                continue
            inner = getattr(obj, "__dict__", {}).get("model", None)
            if inner is None:
                continue
            if "dynamic_pins" not in getattr(inner, "__dict__", {}):
                continue
            patchers.append(obj)
    except Exception as e:
        print(f"VRAM purge: per-module pin scan failed: {e}")
        return report
    for patcher in patchers:
        try:
            freed = patcher.partially_unload_ram(_PURGE_UNBOUNDED)
            report["models"] += 1
            report["freed_mb"] += float(freed or 0) / (1024 * 1024)
        except Exception as e:
            report["failed"] += 1
            print(f"VRAM purge: pin drain failed for {type(patcher).__name__}: {e}")
    report["freed_mb"] = round(report["freed_mb"], 1)
    return report


def _purge_quiesce(tag: str) -> None:
    """Quiesce async copies and release the host RAM cache (no model teardown)."""
    synced = _purge_sync_offload_streams()
    freed = _purge_release_ram_cache()
    print(
        f"VRAM purge[{tag}]: offload_streams_synced={synced} "
        f"ram_cache_released={freed / (1024 * 1024):.1f} MB"
    )
```

## 5. 各部分含义

### 5.1 `_purge_aimdo_lock()`

返回 guard 自身的锁对象，既不是副本，也不是新建的锁。两点性质是关键：

- **同一性。** `lock is guard._NATIVE_LOCK` 为真，因此 purge 与 loader 的原生包装竞争的是同一个对象。若另建一把锁，则不会排除任何东西。
- **按后缀发现。** 在 `sys.modules` 中按名称后缀 `comfy_aimdo_fastdisk_guard` 查找，因为 ComfyUI 以目录派生的包名注册自定义节点（`ComfyUI-HSWQ-Loader-and-Tools.patches.comfy_aimdo_fastdisk_guard`）。按后缀匹配可避免依赖目录名。

返回 `None, None` 表示 guard 未加载：调用方会打印该事实并继续。

### 5.2 `_purge_sync_offload_streams()`

`comfy.model_management.sync_all_offload_streams()` 等待 `STREAMS` 中的每个流，在没有流时回退到 `synchronize()`（`model_management.py:1534`）。这是唯一能保证 offload stream 上不再有拷贝在飞的 core 调用，而这正是 unmap 一个页之前必须成立的条件。

模块、函数或调用不可用时返回 `False`；该布尔值会被打印，因此“跳过的同步”是可见的，而不是被默认成立。

### 5.3 `_purge_release_ram_cache()`

`comfy.memory_management.extra_ram_release(target, free_active=True)` 转发给由 `set_ram_cache_release_state()` 注册的缓存回调，并返回其释放的字节数；尚未注册回调（进程还没加载过模型）时返回 0。请求量为 `1 << 60`，即“释放所有可释放项”；回调会按实际存在量收敛。

`free_active=True` 允许释放属于当前 prompt 的缓存条目，这与节点被要求完成的动作一致：purge 的定义就是丢弃当前驻留。

### 5.4 `_purge_drain_module_pins()`

这是 0.46 的 pin 唯一正确的释放路径，因为 `ModelPatcher.partially_unload_ram()` 会按顺序完成四步（`comfy/model_patcher.py:2202-2227`）：

1. `comfy.pinned_memory.flush_pin(module, module_pin)` —— 把脏 pin 回写到其文件切片，使 fast-disk 承载的权重不会在磁盘上留下陈旧数据。
2. `hostbuf.truncate(offset, do_unregister=registered)` —— 解除注册。
3. `TOTAL_PINNED_MEMORY -= size` 与 `pinned_size[0] -= size` —— 保持记账正确。
4. 更新 `stack_split[0]` —— 保持 balancer 的栈索引有效。

手工重复这四步等于复制 core 的逻辑，并会在下一次 core 变更时漂移。调用自身的回收路径，也意味着注册状态与记账之间不可能被引入不一致。

扫描安全性：仅当 `type(obj).__name__` 为 `ModelPatcher` 或 `ModelPatcherDynamic`，**且**该对象自身的 `__dict__` 含 `model`，**且**该内部对象自身的 `__dict__` 含 `dynamic_pins` 时才接受。不对任意对象做 `dir()` 或 `getattr` 探测，因为第三方惰性加载器会以安装包的方式响应 `__getattr__`。

每次只处理一个 patcher，每个各自在 `try` 中：失败会累加 `failed` 并打印异常，其余 patcher 继续处理。返回的字典 `{"models": n, "freed_mb": x, "failed": k}` 由调用方打印。

### 5.5 `_purge_quiesce(tag)`

入口处的组合：同步 stream、释放 RAM 缓存、打印一行包含布尔值与释放字节数的日志。它刻意**不**触碰模型：在节点入口处计算图可能仍需要它们，而 pin 回收属于显式的 HSWQ 区段。

### 5.6 锁的临界区及其两个释放点

锁在 Method 2（`cudaHostUnregister` 扫描）之前立即取得，跨越 Method 3（gc 核级 storage 销毁）与 Method 2c（comfy_kitchen 缓存重置）保持持有，并在 `soft_empty_cache()` 之后释放。因此该区段覆盖了所有可能 unmap 页的操作。

存在两个释放点，是因为该分支被 `try / except` 包裹：

- 正常路径在分支内最后一次 CUDA 调用之后释放（3703 行）；
- 报告 `Error purging models` 的 `except` 同样会释放（3743 行）。

`_aimdo_held` 在分支开头初始化为 `False`，因此 `except` 绝不会引用未定义的名字，也不可能发生二次释放。

`threading.RLock` 是可重入的：同一线程再次取得是安全的，这一点很重要，因为 loader 的包装可能在同一调用链中已先行持有它。

### 5.7 顺序为何固定

| 步骤 | 为何必须先于下一步 |
| :--- | :--- |
| stream 同步 | 拷贝在飞时 unmap 页，正是被记录的 abort |
| 取得锁 | guard 的原生调用会退掉读取器槽位；purge 不得与之交错 |
| pin 回收 | flush 必须在模块与其文件切片仍可达时完成 |
| pin 解除注册（Method 2） | 旧扫描放在回收之后，使记账已经落定 |
| storage 销毁（Method 3） | 最后一步，在 flush 与解除注册之后 |
| kitchen 重置（2c） | 重置其 storage 已被销毁释放的工作区 |
| 锁释放 | 仅在最后一次 CUDA 调用之后 |

## 7. 限制

pin 回收未在本环境中以真实加载的模型测量：已测证据覆盖锁的同一性、互斥性、core 签名、分派路径与全部跳过路径。实时模型上的实际释放量属于 core 自身的行为，由 `ModelPatcher.partially_unload_ram()` 执行。

## 8. 保持的约束

- 未改动旧的 `PINNED_MEMORY` 扫描、Method 2c、Method 2d，也未改动各家族 purge 的顺序。
- 未新增节点输入，未新增开关。
- 代码中无绝对路径、无环境专有值。
- 根目录与 `nodes/purge_vram.py` 逐字节一致，符合包的要求。
