## 1. 概述与核心升级

在 `v2.5.0` 中，`Patch Sage Attention DM` 节点的 `spargeattn` 模式完成了对 **SpargeAttn-hswq**（fork >= 1.1）最新底层 API 的全量对齐（对齐 `ComfyUI-SeedVR2-VideoUpscaler-with-TensorRT` 的前沿集成标准）。

本次升级重点解决了每步 Attention 调用的转置拷贝开销、Softmax Scale 契约传递失效、内部异常双重回退等深层隐患，并在 Blackwell / Ada / Hopper 架构上通过实测保障了逐位一致性（Bit-Exact）。

---

## 2. 背景与架构演进

在 v2.4.7 引入的初始 `spargeattn` 实现中，内核调用固定走 `spas_sage2_attn_meansim_topk_cuda`。该接口强制要求 HND（`[batch, heads, seq, dim]`）布局。

然而，ComfyUI 在默认执行链路（`skip_reshape=False`）中向 Attention 函数传入的是 NHD（`[batch, seq, heads, dim]`）布局张量：
- **旧方案开销**：每次 Attention 调用前，必须对 $Q, K, V$ 执行 3 次 `.transpose(1, 2).contiguous()`，在 CUDA 内部申请新的物理显存缓冲区并搬运数据；计算完成后还需对输出执行转置恢复。在包含数十层 DiT/Transformer 结构的生成过程中，转置操作带来了可观的显存带宽浪费与内核调度抖动。
- **新方案升级**：SpargeAttn-hswq fork 1.1+ 原生引入了专用的 `spas_sage2_attn_meansim_topk_nhd_cuda` 算子，能够直接在 NHD 布局下完成两阶段块稀疏索引与 SageAttention2++ 量化计算，实现完全的零拷贝（Zero-Copy）执行。

## 3. 核心改进详解

### 3.1 NHD 零拷贝入口与双重分发路径

`get_sparge_func_dm()` 内部构建了基于张量布局与运行时支持的双重动态分发体系：

```python
# 补丁应用时一次性解析入口点（非每次前向运行时反射）
nhd_entry = getattr(spas_module, "spas_sage2_attn_meansim_topk_nhd_cuda", None)
hnd_entry = getattr(spas_module, "spas_sage2_attn_meansim_topk_cuda", None)
```

在前向计算时，根据 `skip_reshape` 状态自动选择最佳算子路径：
- **`skip_reshape=False`（ComfyUI 标准 NHD 传入）**：若环境安装了 fork >= 1.1，直接调用 `nhd_entry(q, k, v, ...)`，彻底消除 $Q, K, V$ 的转置开销。若为旧版 fork，则自动保留安全的 HND 局部转置路径。
- **`skip_reshape=True`（已为 HND 格式传入）**：直接调用成熟的 `hnd_entry(q, k, v, ...)`。

### 3.2 Softmax Scale 契约完整透传

ComfyUI 0.38.x 规范在 Attention 包装器中支持传入可选的 `kwargs["scale"]`（如针对特定模型定制的注意力缩放因子）。

- **此前缺陷**：旧版本未接收 `scale` 参数，SpargeAttn 内核始终使用内建默认值 $1/\sqrt{d}$。当模型指定了自定义缩放因子时，计算结果存在数值偏差。
- **本次改进**：提取 `kwargs.get("scale", None)` 并直接透传给 SpargeAttn 内核（内核接受 `sm_scale` 参数）以及 PyTorch SDPA 回退分支，确保严格数学等价。

### 3.3 ComfyUI 0.38.x `low_precision_attention` 退出门

新增对 ComfyUI 核心低精度控制开关的响应：

```python
if kwargs.get("low_precision_attention", True) is False:
    return comfy_attention.attention_pytorch(
        q, k, v, heads, mask=mask,
        skip_reshape=skip_reshape,
        skip_output_reshape=skip_output_reshape,
        **kwargs
    )
```

当工作流或内部管道显式指定 `low_precision_attention=False` 时，即刻绕过量化稀疏内核，干净路由至原生 FP16/BF16 `attention_pytorch`，与原生 `attention_sage` 行为保持完全一致。

### 3.4 内部 SDPA 回退张量布局修正

在 v2.4.7 中，当遭遇 Attention Mask、不支持的 Head Dim（非 64/128）或序列长度 $< 128$ 时，内部回退代码直接调用 `attention_pytorch(q, k, v, heads, ...)`。

- **问题**：在 `skip_reshape=False` 时，传入的 $Q, K, V$ 为 NHD 布局，直接传给未声明 `skip_reshape` 的 `attention_pytorch` 会触发张量形状断言失败，导致在内部回退分支中二次抛出异常，只能依赖外层的兜底 `try...except` 再次抢救。
- **修复**：规范透传 `skip_reshape=skip_reshape` 和 `skip_output_reshape=skip_output_reshape`，确保内部回退一击即中、零多余开销。

### 3.5 补丁时一次性解析与安全降级

算子入口解析移至 `get_sparge_func_dm()` 补丁初始化时执行一次并记录日志，避免了在高频推理循环中的反射查询开销。若运行环境中缺失 SpargeAttn 关键入口，不会抛出未捕获的裸 `AttributeError`，而是优雅记录警告并回退至 PyTorch SDPA。

## 4. 硬件实测与逐位一致性验证

在 GeForce RTX 5060 Ti（sm120，Blackwell 架构）及 SpargeAttn-hswq 1.2.1 wheel 环境下进行了全量精度与行为比对验证：

| 测试项 | 对比条件 | 测量指标 | 验证结论 |
|---|---|---|---|
| **NHD vs HND 精度** | FP16, topk=0.5 | Max Absolute Difference | **0.0 (Bit-Exact)** |
| **NHD vs HND 精度** | BF16, topk=0.5 | Max Absolute Difference | **0.0 (Bit-Exact)** |
| **HND skip_reshape** | skip_reshape=True vs NHD | 数值一致性 | **0.0 (Bit-Exact)** |
| **Scale 透传** | 显式 scale vs 默认值 | 激活输出差 | **0.086 (有效生效)** |
| **GQA 支持** | 展开 KV 内核 vs 紧凑输入 | 结果一致性 | **0.0 (严格相等)** |
| **Mask / 约束回退** | mask 存在 / seq < 128 | 与原生 SDPA 比对 | **0.0 (严格等价)** |
| **退出门回退** | low_precision_attention=False | 与 attention_pytorch 比对 | **0.0 (严格等价)** |

## 5. 工作流兼容性与依赖要求

1. **即插即用**：既有已保存工作流中的 `Patch Sage Attention DM` 节点无需任何改动，原本选定 `spargeattn` 的工作流将在加载时自动享受零拷贝加速。
2. **底层 Wheel 支持**：推荐在 ComfyUI Python 环境中安装最新的 `spas_sage_hswq_attn` 预构建 wheel：
   - [Hugging Face: Sage-Attention-and-Sparge-Attention-HSWQ](https://huggingface.co/ussoewwin/Sage-Attention-and-Sparge-Attention-HSWQ)
3. **既有 SageAttention 模式保持完全隔离**：`auto`、`cuda`、`triton`、`sageattn3` 路径保持纯净独立，未受任何改动影响。
