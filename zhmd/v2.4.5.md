## 1. 架构意义与技术背景

### 1.1 Krea2 ConvRot NVFP4 执行流水线

在 `ComfyUI-HSWQ-Loader-and-Tools` 的最新更新中，Krea2 DiT 模型引入了专用的 **ConvRot NVFP4（Tensor Core）** 推理流水线，以及混合式 **低秩 LoRA 残差烘焙（Low-Rank LoRA Residual Baking）** 机制。该架构涉及多个相互依赖的层级：

1. **基于已打包权重的低秩 LoRA 残差累加（`_hswq_krea2_lora_res` / `_hswq_krea2_lora_res_gpu`）**：
   - 在标准权重烘焙中，将 LoRA 权重应用到 4-bit 量化矩阵需要经历 反量化 $\to$ 叠加差量 $\to$ 重新量化为 NVFP4。由于微小风格 LoRA 权重引入的微差量极小（约为权重 $a_{max}$ 的 $0.1\% - 0.8\%$），直接进行 4-bit 重新量化（每个编码的步长约为 $4\% - 8\%$）会抹除精细细节，破坏高频风格特征。
   - 为了在不损失量化精度的情况下保留完整数学精度，Krea2 在显存中保持基础 4-bit 张量处于打包状态，并将未量化的 LoRA 差量作为低秩分解的 down/up 投影直接存储在 `torch.nn.Module` 实例上：
     $$\Delta W = \text{scale} \cdot (\text{mat\_up} \times \text{mat\_dn})$$
   - 这些低秩张量存储在嵌套的元组列表中：
     `_hswq_krea2_lora_res = [(mat_dn_0, mat_up_0, scale_0), (mat_dn_1, mat_up_1, scale_1), ...]`
   - 此外，预分配的 GPU 暂存缓冲区缓存在 `_hswq_krea2_lora_res_gpu` 中。
2. **Krea2 Ops 包装与调度层级**：
   - `comfy.ops.mixed_precision_ops` 被 `_hswq_krea2_stack` 包装，以动态注入 Krea2 NVFP4 Tensor Core Linear 算子。
   - `comfy.utils.convert_old_quants` 被 `_hswq_krea2_oldquants` 拦截，以处理旧版量化检查点。
   - `comfy.model_detection.detect_unet_config` 通过 `_hswq_krea2_txtlayers_fix` 被打补丁，以修正由打包 Projector 维度检测引起的 `txtlayers=8` 误判，确保 12 层 CLIP 条件处理正常运作。
   - `ModelPatcherDynamic.load` 与 `comfy.model_management.load_models_gpu` 被拦截以附加动态 Krea2 烘焙钩子。
3. **模块级池化与 CUDA Graph 分配**：
   - `_ACT_Q_POOL`（激活量化缓冲区池）、`_ROT_OUT_POOL`（旋转矩阵输出缓冲区池）、`_GRAPH_CACHE`（CUDA Graph 实例）及 `_HADAMARD_CACHE` 常驻于全局模块内存中。

### 1.2 既往清理实现中的故障模式

在此次更新（`v2.4.3`）之前，触发 HSWQ 清理会残留若干严重故障隐患：

- **隐式显存泄露与残差交叉污染**：
  - 旧版 `_empty_cuda_tensor` 与 `_kill_tensor_storage` 函数仅检查顶层 `torch.Tensor` 实例（`if torch.is_tensor(t)`）。
  - 由于 `_hswq_krea2_lora_res` 是元组容器的 `list`，内部的 `mat_dn` 与 `mat_up` GPU 张量在内存扫描中被跳过。这些张量持续滞留于显存中，导致显存无法回收，并在后续模型加载时造成过时 LoRA 残差污染。
- **未剥离的全局包装器与模型破坏**：
  - 在卸载 Krea2 模型时，若未剥离 `_hswq_krea2_stack`、`_hswq_krea2_oldquants` 和 `_hswq_krea2_txtlayers_fix`，后续加载 SDXL、Flux 或 Z Image 模型时将误走 Krea2 专用算子与错误的 UNet 配置检测逻辑。
- **陈旧 CUDA Graph 与缓冲区不同步**：
  - 持久化的 CUDA Graph 实例引用了已被销毁或重新分配的张量地址，导致后续生成发生非法内存访问（`CUDA error: invalid argument` / `PyCapsule` 调用错误）。

## 4. 技术分析与实现机制

### 4.1 针对张量内存销毁的递归容器遍历

```python
                    def _empty_cuda_tensor(t) -> None:
                        if t is None:
                            return
                        if torch.is_tensor(t):
                            try:
                                data = getattr(t, "data", t)
                                if not bool(getattr(data, "is_cuda", False)):
                                    return
                                empty = torch.empty(0, dtype=data.dtype, device=data.device)
                                t.data = empty
                            except Exception:
                                pass
                            return
                        # Nested containers (e.g. _hswq_krea2_lora_res = [(mat_dn, mat_up, scale), ...])
                        if isinstance(t, (list, tuple)):
                            for item in t:
                                if item is not None:
                                    _empty_cuda_tensor(item)
                        elif isinstance(t, dict):
                            for v in t.values():
                                if v is not None:
                                    _empty_cuda_tensor(v)
```
- **机制原理**：在 PyTorch 中，将对象赋值为 `None` 或调用 `delattr` 仅能减少 Python 引用计数。若存在循环引用或外部命名空间引用，底层 CUDA 内存分配仍将停留在 GPU 中。`_empty_cuda_tensor` 通过 `torch.empty(0, dtype=data.dtype, device=data.device)` 就地替换底层的 `Tensor.data` 指针，强制 PyTorch CUDA caching allocator 立即释放其物理显存。
- **递归容器处理**：支持 `list`、`tuple` 及 `dict` 结构，递归遍历任意深度的嵌套容器，确保 `_hswq_krea2_lora_res` 中的每个低秩张量元组 `(mat_dn, mat_up, scale)` 均被彻底置空。

### 4.5 `_kill_tensor_storage` 递归释放与模块显存销毁

```python
                def _kill_tensor_storage(t) -> int:
                    if t is None:
                        return 0
                    if isinstance(t, (list, tuple)):
                        freed_nested = 0
                        for item in t:
                            if item is not None:
                                freed_nested += _kill_tensor_storage(item)
                        return freed_nested
                    if isinstance(t, dict):
                        freed_nested = 0
                        for v in t.values():
                            if v is not None:
                                freed_nested += _kill_tensor_storage(v)
                        return freed_nested
                    freed = 0
                    try:
                        data = getattr(t, "data", t)
                        if getattr(data, "is_cuda", False):
                            sz = int(data.nelement()) * int(data.element_size())
                            freed += sz
                            t.data = torch.empty(0, dtype=data.dtype, device=data.device)
                    except Exception:
                        pass
                    return freed
```
- **机制原理**：在 `_kill_module_vram` 中，使用 `if val is not None:` 确保列表、元组等容器对象直接传入 `_kill_tensor_storage`，在删除模块属性前递归清空其全部嵌套 CUDA 存储。
