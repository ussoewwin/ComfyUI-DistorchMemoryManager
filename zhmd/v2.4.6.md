## 1. 执行摘要与技术背景

`ComfyUI-DistorchMemoryManager` 的 **v2.4.6** 版本针对 HSWQ INT8 / NVFP4 深度显存清理流程中遇到的内存管理缺陷进行了全面修复：

1. **抑制误报 Unpin 警告**：彻底解决 Purge VRAM 执行期间频繁出现的 `[WARNING] Tried to unpin tensor not pinned by ComfyUI` 警告日志刷屏。
2. **防止 CUDA 驱动异常中止**：根除因对 PyTorch 主机页锁定内存非法调用 `cudaHostUnregister` 导致的 `Fatal Python error: Aborted` 致命崩溃。
3. **TCON NVFP4 TC 算子重新武装**：在 HSWQ 堆栈剥离后强制重置执行器缓存，确保下一次生成能重新正确初始化 Tensor Core (W4A4) 算子，杜绝第二次生成出现噪点图像。
4. **废弃 Detailer / PinCache 残留扫描**：伴随 HSWQ 彻底移除 Pin Buffer Cache，同步删除 Distorch 内过时的 PinCache 排空与 Detailer SEGS 扫描逻辑。

## 2. 故障根本原因深度分析

### 2.1 Unpin 警告日志刷屏（`Tried to unpin tensor not pinned by ComfyUI`）

在 `_kill_tensor_storage` 或 GC 扫描中遍历到 `tensor.is_pinned() == True` 的张量时：
- 由 PyTorch 原生分配的页锁定内存（如 `torch.empty(..., pin_memory=True)`、DataLoader 管道或 Detailer SEGS 裁剪张量），其 `is_pinned()` 均返回 `True`。
- 但是，此类张量从未被注册到 ComfyUI 的内部跟踪字典（`comfy.model_management.PINNED_MEMORY`）中（该字典仅记录通过 ComfyUI `mm.pin_memory()` 执行 `cudaHostRegister` 的缓冲区）。
- 当直接对不存在于 `PINNED_MEMORY` 中的内存指针调用 `mm.unpin_memory(tensor)` 时，ComfyUI 核心代码会无条件触发 `logging.warning("Tried to unpin tensor not pinned by ComfyUI")`。

### 2.2 CUDA 驱动中止崩溃（`Fatal Python error: Aborted`）

- PyTorch 中的主机固定（Pinned）内存分为两种本质不同的机制：
  1. **主机直接分配内存**（`cudaHostAlloc` / `cudaMallocHost`）：由 PyTorch 内存分配器直接申请的页锁定物理页。在 CUDA 规范中，严禁对此类内存调用 `cudaHostUnregister`，否则会直接返回 `cudaErrorInvalidValue`。
  2. **主机注册内存**（`cudaHostRegister`）：将普通可分页内存注册到 GPU MMU 页表。仅有此类内存可以且必须使用 `cudaHostUnregister` 解除注册。
- 当旧版代码对未在 `PINNED_MEMORY` 中记录的 Pinned 张量指针直接调用 `cudaHostUnregister(data.data_ptr())` 时，CUDA 驱动层的页表管理状态被严重破坏。
- 随后，当执行清理 NVFP4 运行时池（`clear_nvfp4_runtime_pools`）释放 `_ACT_Q_POOL` / `_ROT_OUT_POOL` 或调用 `torch.cuda.empty_cache()` 时，CUDA 运行时检测到内部状态不一致，立刻向 Python 进程发送 SIGABRT 信号，造成 `Fatal Python error: Aborted`。

### 2.3 TCON NVFP4 第二次生成噪点与 TC 算子重新武装

- 在 HSWQ purge 剥离算子包装、Hadamard 缓存与运行时池后，ComfyUI 的执行图缓存中仍保留了先前 Loader 节点的输出引用。
- 在下一次生成时，PromptExecutor 会直接复用已剥离算子的 ModelPatcher 实例而不再重新执行 Loader 节点，导致 Tensor Core (W4A4) 算子未被正确重新武装，引发数值计算偏差并输出噪点图。

## 3. 架构与实现修复规范

### 3.1 `mm.unpin_memory` 的严格 `PINNED_MEMORY` 校验门控

```python
if bool(getattr(data, "is_pinned", lambda: False)()):
    try:
        import comfy.model_management as mm
        _pm = getattr(mm, "PINNED_MEMORY", None) or {}
        _ptr = data.data_ptr()
        if _ptr in _pm:
            # 仅对已在 ComfyUI 中登记的张量执行 unpin，保持账目完全一致
            mm.unpin_memory(data)
    except Exception:
        pass
```

仅对明确记录在 `mm.PINNED_MEMORY` 中的指针调用 `mm.unpin_memory()`。对于未记录的张量直接安全跳过，彻底避免产生任何警告日志。

### 3.2 彻底移除对未注册张量调用 `cudaHostUnregister` 的非法操作

在 `_kill_tensor_storage` 及 `Method 3` 中，完全删除了所有针对未验证指针的 `cudaHostUnregister()` 裸调用。`cudaHostUnregister` 仅严格在 `_force_unregister_comfy_pins()` 中针对经过验证的 `PINNED_MEMORY` 键值执行。

### 3.3 注入队列标志以重置执行器缓存并强制重新加载

```python
try:
    mm.unload_models = True
    mm.free_memory = 1e30
except Exception:
    pass
```

强制 PromptExecutor 废弃已缓存的 Loader 节点输出，确保后续工作流重新执行 Loader，完整重新初始化 Tensor Core 算子堆栈。

### 3.4 清除陈旧的 PinCache 与 Detailer SEGS 扫描逻辑

从 `nodes/purge_vram.py` 与 `purge_vram.py` 中彻底移除了无用的 `_drain_hswq_pin_cache` 和 `_purge_detailer_segs_and_executor_cache`，使 Purge VRAM 的执行链路更为轻量、纯粹与高效。
