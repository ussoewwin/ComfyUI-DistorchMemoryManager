## 1. 概述与核心变更

**v2.5.2** 中，**Patch Sage Attention DM** 节点（`nodes/sa.py`）合并了 [PR #5](https://github.com/ussoewwin/ComfyUI-DistorchMemoryManager/pull/5)（[@IrradiatedHaggis](https://github.com/IrradiatedHaggis)，*SA Patch Node restores previously set user attention rather than forcing FA2*）。清理路径不再强制使用 Flash-Attention，而是恢复 ComfyUI 依启动参数配置的注意力后端；其他组件安装的 override 在清理时也会保留。

在合并分支之上，本次发布新增两个可选后端（`fa2` 与 `comfy kitchen attention`），把仅 sm80 可用的 fp16 累加模式在 Blackwell 上改走 fp8 内核，修复了导致所有 SageAttention 模式回退到 PyTorch 注意力的未定义变量错误，并把节点显示名与控件键统一为 `accel` 术语。

---

## 2. 合并的 PR #5

### 2.1 清理恢复已配置的后端

- **此前**：清理回调总是重新安装 `attention_flash`，因此以 `--use-pytorch-cross-attention`（或其他后端）启动的会话，在节点释放模型后会落在 Flash-Attention 上。
- **现在**：`_restore_previous()` 把节点打补丁前捕获的 override 原样放回；若此前没有 override，则将其整体移除。全局 `comfy.ldm.modules.attention.optimized_attention` 对象从不被改写。

### 2.2 清理日志报告实际生效的后端

- **此前**：恢复日志无论实际恢复成什么，都打印 Flash-Attention 信息。
- **现在**：该行由 `report_flash` 门控。`disabled` 只打印恢复行；安装后端的各模式保持节点一贯的两行形式。

### 2.3 保留其他组件的 override

- **问题**：在本节点之后打补丁的节点（例如稀疏注意力节点）会安装自己的 `optimized_attention_override`，此前的清理会把它替换成打补丁时捕获的状态。
- **现在**：清理时比较当前 override 与本节点安装的 override。若不一致，则保留其他组件的 override，仅输出一行恢复日志。

## 3. 新增的注意力后端

### 3.1 `fa2`：显式选择 Flash-Attention

- 解析已安装的 `flash-attn` 构建，并输出 `[ComfyUI] Using FA-2|FA-3 (Flash-Attention <version>) direct`。
- 无法导入 `flash-attn` 时，节点输出原因、保持此前配置的后端，且不安装 override。

### 3.2 `comfy kitchen attention`：Comfy Kitchen INT8 注意力

按 ComfyUI 自身 **Model Attention Backend** 节点的同一路径解析：

- 以无默认值方式调用 `comfy_attention.get_attention_function("comfy_kitchen_int8", None)`；后端未注册时以 ComfyUI 自身的警告文案回退到 PyTorch 注意力：`Attention backend 'comfy kitchen attention' is unavailable; using PyTorch attention.`
- override 与 `ModelPatcher.set_model_optimized_attention` 形状一致，包含从解析到的后端继承 `container_function`。因此注意力张量容器仍走 `prequantize_int8_attention` → `int8_attention_from_prequantized` 路径，峰值内存行为与原生节点一致。
- 按 SageAttention 各模式的方式记录解析到的构建：`Patching comfy attention to use Comfy Kitchen <version>+cu<cuda>torch<torch>`。

## 4. Blackwell 内核分派

- **问题**：`sageattn_qk_int8_pv_fp16_cuda` 仅为 `sm_80` 构建（`setup.py` 中 `_qattn_sm80` 的 arch 列表为 `["8.0"]`）。在 sm100/sm120/sm121 上调用会抛出 `CUDA error: no kernel image is available for execution on the device`。
- **现在**：在 sm100/sm120/sm121 上，该选项解析为 `sageattn_qk_int8_pv_fp8_cuda`，使用 `qk_quant_gran="per_warp"` 与 `pv_accum_dtype="fp32+fp16"`（CUDA 12.8 以下为 `"fp32"`），与 `sageattention/core.py` 自身的分派逻辑一致。分派时输出一行日志：`SageAttention: sm120 has no fp16-accumulate kernel; using the fp8 kernel (qk_quant_gran=per_warp, pv_accum_dtype=fp32+fp16)`。
- 选项名称直接标注约束：`sageattn_qk_int8_pv_fp16_cuda (for only sm80)`。

---

## 5. 缺陷修复

### 5.1 未定义的 `is_causal` 导致所有 SageAttention 模式回退

- 包装器调用引用了未定义的 `is_causal`，导致每个 SageAttention 模式抛出 `NameError: name 'is_causal' is not defined`，ComfyUI 输出 `Error running sage attention: ... using pytorch attention instead.`
- 现改为 `is_causal=False`，与 ComfyUI 自身 `attention_sage`（`attention.py`）传入的值一致。

### 5.2 日志中的版本后缀重复

- `sageattention.__version__` 本身已携带本地标签（`2.2.0.post6+cu134torch2.15.0`），日志行仍在其后再拼接 `+cu<cuda>torch<torch>`。
- 现仅当包版本不含本地标签时才拼接。另将 `torch.version.__version__`（返回完整的 `2.15.0+cu134`）改为取发行版本部分。

---

## 6. 节点更名与控件键

- 显示名：`Patch Sage Attention DM` → **`Patch Accel Attention DM`**（`NODE_DISPLAY_NAME_MAPPINGS`，`__init__.py`）。
- 控件键：`sage_attention` → **`accel_attention`**。选项值未改动，已保存的工作流仍保留其内核标识符。
- 类名 `PatchSageAttentionDM` 与注册键保持不变，以维持工作流兼容。

## 7. 验证与兼容性

### 7.1 实测结果

环境：RTX 5060 Ti（sm120）、torch 2.15.0+cu134、CUDA 13.4、sageattention 2.2.0.post6、comfy_kitchen 0.2.40。

| 检查项 | 结果 |
| --- | --- |
| `comfy kitchen attention` 与 ComfyUI `Model Attention Backend`（普通 / mask / skip_reshape / GQA / container） | 输出 `torch.equal` 相等，内核到达次数相同 |
| `SpatialTransformer` 前向，原生节点与本节点 | `torch.equal` = True，最大绝对差 0.0 |
| `comfy_kitchen.int8_attention` 与 PyTorch SDPA，head_dim 64 / 128 | cosine 0.99989951 / 0.99989319，最大绝对差 0.005951 / 0.005737 |
| `comfy_kitchen.int8_attention` 速度，B=1 H=24 D=128 | 1.65x（1,024）/ 2.84x（4,096）/ 2.88x（16,384） |
| 分派前在 sm120 上调用 `sageattn_qk_int8_pv_fp16_cuda` | `CUDA error: no kernel image is available`，回退到 PyTorch 注意力 |
| sm120 上 `sageattn_qk_int8_pv_fp8_cuda` per-warp | 输出有限、形状正确 |
| sm120 上 `sageattn_qk_int8_pv_fp16_triton` | 输出有限、形状正确 |
| `disabled` | 未安装 override，全局注意力后端不变 |
| 分支测试 / live 节点测试 / 实内核测试 | FAILURES: 0 |

### 7.2 兼容性

- 选项值未改动，既有工作流可继续使用。
- `allow_compile` 仍为可选输入；`fa2` 与 `comfy kitchen attention` 不使用 `torch.compile`，对其忽略。
- Comfy Kitchen 后端要求 ComfyUI 构建已注册 `comfy_kitchen_int8`；未注册的构建会回退到 PyTorch 注意力并在日志中说明。
